# 水中翼ボート 1日目 復元候補

`control/`と`communication/`を組み合わせて使用する。

## 構成

- 大会コースは A → B → C → D → E → F → G → H → C → B → A。
- 円弧上の通過点生成・円弧後の補間点・ゲート追従・復帰処理を保持する。
- 制御出力（Pitch/Roll/Height/Yaw）へのLPF処理とその操作欄を除去する。ToF等の計測値の前処理は保持する。
- GNSS詳細状態パネル、GNSS診断を含む診断ページ・API・イベント収集を除去する。GNSS測位・位置送信・地図・航行に必要な条件判定は保持する。
- BNO08Xは地磁気を使うRotation Vectorと磁気レポートを使用する。方向制御はIMU方位・角速度を用いる。
- 状態通知は100 ms。IMU有効性・鮮度は航行のみモードでも要求する。
- LPFの通信フィールドはペイロードの整合のため予約欄として残す。送信値は0固定、制御側は非0を拒否し、LPF計算処理自体は存在しない。
- GNSS移動方向の窓推定は診断値として残るが、後翼の方向入力・開始条件には使用しない。

## 復元根拠と範囲

基点は `temesotejam/2026_8_6` の `0820d1d1c2107609c839bf6cc5d8c42f9d56e982`（保存用リポジトリの整形済みday2）。両日共通だった円弧生成と11点プリセットを保持し、使用者の説明および従来コードで確認できる差を戻した候補である。

旧bf8067cへプリセットだけを足した版とは異なり、円弧生成を含む構成である。当日のバイナリをそのまま回収したものではない。

後翼の駆動量条件、離水移行、ToF復旧・有効値保持、低帯域送信方式、危険角停止無効など、今回の情報だけで変更時期を確定できない処理は基点から保持した。追加の推測で旧版へ戻していない。GNSS配線設定も基点のRX=D7/TX=D6を保持する。

## ビルド

PlatformIOで各フォルダのplatformio.iniを開く。ボードはXIAO ESP32S3。

```sh
pio run -d control -e production
pio run -d communication -e production
```

通信ペイロードを含めて対にした候補なので、別版の片側と混用しない。実機への書き込み・水上での動作確認は今回の検証に含まない。

# 水中翼ボート 制御プログラム保存版

報告書で扱う1日目・2日目の使用版として指定されたプログラムを、通信側・制御側の組で保存しています。

**書き込み・プログラムZIP： https://temesotejam.github.io/hydrofoil-boat-control-archive/**

| 保存先 | 使用日 | 方向制御 | 制御出力LPF | 状態通知 |
| --- | --- | --- | --- | --- |
| `day1/` | 1日目（8月8日） | 地磁気を使うBNO08XのIMU方位 | なし | 100 ms |
| `day2/` | 2日目（8月9日） | GNSS位置変化から求めた移動方向 | あり | 2秒 |

両日とも、大会コース **A → B → C → D → E → F → G → H → C → B → A** の11点をまとめて送り、円弧上の通過点を生成して連続追従します。コースの基準点・円弧生成・通過点追従を両日の変更点として扱いません。

1日目にはLPFの操作欄・GNSS診断画面がなく、2日目にはそれらがあります。航行のみモードでは、1日目は方向制御にIMUが必要です。2日目はGNSS移動方向を使用し、姿勢補助を選んだ場合にロール・ピッチ用のIMUも必要です。

自動航行の基準要求は両日とも1.00（100%）です。画面の「VESC最大Duty」を1.00にすると、電源等の制限がない場合の目標Dutyが100%になります。最大Dutyを0.50にすれば目標は50%です。加速処理・電源保護・通常停止・緊急停止は保持します。Dutyは回転数の割合ではありません。

## ブラウザから書き込む

1. 公開ページをPC版ChromeまたはEdgeで開く。
2. 使用日を選ぶ。通信側と制御側は必ず同じ日の版を組み合わせる。
3. モータ・サーボの外部電源を切り、対象XIAO ESP32S3だけをUSB接続する。
4. 対応する基板の書き込みボタンを押す。
5. 完了後、もう一方の基板へ差し替えて同じ日の版を書き込む。

対象はXIAO ESP32S3、8MBフラッシュ。書き込みにより基板上のプログラムや設定が消去される場合があります。

## プログラムだけのZIP

公開ページから各日の「2台分」「制御側だけ」「通信側だけ」を取得できます。ビルドに必要なソース・設定とREADMEを含み、サイト・他の日・テスト・ビルド生成物は含みません。

```sh
python -m pip install platformio==6.1.19
python -m platformio run -d day1/control -e production
python -m platformio run -d day1/communication -e production
python -m platformio run -d day2/control -e production
python -m platformio run -d day2/communication -e production
```

## 保存と検証

使用版の指定とファイルの来歴は区別して記録します。1日目は保存済み2日目コードを基に既知の差を戻したコードを使用者が1日目版として指定したもの、2日目は原典`temesotejam/2026_8_6`の`0820d1d`に対応する保存版です。1日目の参照スナップショットは`88bed77`の`reconstruction/day1/`です。具体的な参照とSHA-256は`archive.json`に保存します。

`verify_archive.py`は1日目の指定スナップショットと2日目の原典に、使用者が確認した自動航行要求100%の修正だけを加え、それ以外のコードが一致することを検証します。旧bf8067cにプリセットだけを足した版は、現在の1日目として使用しません。過去の内容はGit履歴に残っています。

```sh
python scripts/host_tests.py
python scripts/build_site.py
```

1日目の円弧168通過点生成、IMU異常・期限切れ、LPFなしの応答、画面の19項目と入力検証を確認します。両日・両基板の計4種類を実際のArduino/ESP32環境でビルドしてから公開します。

2日目の元の`controller_test.cpp`には古いServoTuning APIとの不整合があり、そのままの実行を合格扱いしません。通信側の古いホスト用スタブが網羅しないAPIもあるため、ファームウェアの実ビルドで確認します。

初回ビルド時は依存ライブラリを取得します。原典でバージョン固定のない依存があるため、再ビルドしたバイナリの完全な再現性は別途管理が必要です。実機への書き込み試験は自動検証に含みません。

保存元の自動航行基準値0.55は、使用者が確認した両日の設定1.00に修正し、来歴と適用範囲をarchive.jsonに記録しています。状態通知や始動確認の時間設定は保持しています。
